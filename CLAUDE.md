# Matthew Study

How this repo behaves. The artifact contract lives in
`matthew_study_style_reference.md` and is authoritative over this file. A
28-unit literary-canonical study of Matthew, live at
https://lanehaden157.github.io/Matthew/ . Research happens in a Claude.ai
project; its output lands here.

Built on **bible-core** (vendored in `biblecore/`, version in
`biblecore/CORE_VERSION`). The shared shape and the ways a book is expected to
differ are in `bible-core/ARCHITECTURE.md`; shared wording defaults in
`bible-core/canon/conventions.md`. The chat-side loop is `core-workflow.md`
(vendored, synced); `CHAT_SIDE_INSTRUCTIONS.md` is pasted by hand into the project's
instruction field (core's template shape; the texts and commentary it leans on are in
`resources.md`, the 28-unit map in `matthew-literary-unit-map.md`). Optional components (echo, itin, compare, synoptic) come
from core's registry via `book.json` `components`; `css/core.css`,
`css/components.css`, `css/division.css`, `data/components.json` and
`components-reference.md` are generated by the build. The book's own look is
`css/theme.css` (rings, triads, the exodus table, the prayer block, the Greek
title).

**State:** `python -m biblecore book` prints where the book stands (units
built and planned, tracked threads, core pin vs vendored copy, sync and paste
status), read from its data. It isn't written here, so it can't go stale.

## Boxed units 1-13 (since 2026-10-01)

Units 1-13 shipped before Matthew moved onto core and are stamped
`"contract": "legacy"` (units.json row and meta block; ARCHITECTURE §5). They
are held to no versioned fragment check, `migrate` leaves them alone, and their
prose and structure stay as they were built. Threads are book-wide, so a new
thread still gets tagged into them: through `retrofit` and `data-w`, never by
re-porting a boxed unit. Diff a boxed unit before committing; a change beyond
tags is a stop. Units from 14 on go through core's loop like Numbers and
Joshua. The old pipeline is in `archive/pipeline/` (not run; the pre-core
state is at tag `pre-revert-2026-09-29`).

## Commands (run from this folder)

    python -m biblecore book             # where the book stands (see State above)
    python -m biblecore port 15 [--dry]  # port source-artifacts/matthew_15_translation.html (--force re-ports)
    python -m biblecore build            # everything downstream of units/*.html
    python -m biblecore audit            # tracked-thread coverage (--ids ROOT to preview an id set)
    python -m biblecore test [--quick]   # check the book: pin, units, contracts, build idempotence
    python -m biblecore sync             # mirror chat-side files, commit and push (after Lane's OK)

`python -m biblecore` lists the rest: `colour` and `data-w` for promoting a
thread, `retrofit`, `leads`, `corpus`, `fetch`, `migrate` after re-vendoring
(it skips the boxed units), `sync-check --mark-pasted` after pasting the
instruction field. **Fresh clone:** `python -m biblecore fetch` once (MorphGNT +
LXX, pinned and sha1-checked, git-ignored in `corpus/`), then `corpus`.

GitHub Actions runs `python -m biblecore test` on every push
(`.github/workflows/tests.yml`, from bible-core's template; commits touching
only `project-side/` or session files skip it).

`book.json` holds everything book-specific (closed keys: an unknown key is an
error). Change behaviour for this book by adding a book-local module that
wraps a core function, not by editing `biblecore/`; `python ../bible-core/tools/core_diff.py`
reports edits made there. Update the vendored copy with
`python ../bible-core/tools/core_sync.py .` (a core release does this for
every book).

**Concurrent sessions.** Another session may be editing `../bible-core` or this
repo at the same time. See "Concurrent sessions" in `../bible-core/CLAUDE.md`:
check `git status` first, work in a worktree if it's dirty, stage explicit
paths, and check `book.json`'s `core` version after vendoring.

## Policy files

`data/threads.json` and `data/roots.json` are policy: the porter proposes, a
human applies. Tracked threads are one Greek lexical root each (a lemma id set
in `roots.json`; a phrase title like *son of David* is a `seq`). Fixed titles
Matthew repeats verbatim are the exception. Claude decides whether a candidate
is promoted, biased toward book-wide, and asks Lane by popup when unsure (the
style reference §2). Thread colours come from `python -m biblecore colour`;
eyeballed colours collided before, so hand-pick one only if Lane asks.

Promoting a thread makes every occurrence in every built unit need `data-w`,
boxed units included. Usually `python -m biblecore data-w N` fills them in
place; what it can't decide, and the port's coverage gaps, go in
`retrofit/retrofit-tags.json`.

**Retrofit recipe** (per promoted root, per unit, for the verses `data-w`
reports as undecided):

1. Compare the root's occurrences in `Matthew-words.tsv` for the verse with the
   fragment's `<span class="r" data-root="ROOT">` spans, in order.
2. Where the counts differ, look closer: one span over two source words (one
   `retag`, or split by hand); one source word as two English spans (keep the
   span a reader recognises as the word and `unwrap` the other, or give both
   the same `w` with `retag`'s `occ`); or a truly untagged occurrence (`add`).
3. Same root and same text twice in a verse: `retag`'s `occ` (1-based); for
   `add`, the `w` makes each entry idempotent on its own word id.
4. One entry per occurrence: `{"unit", "verse", "from", "to", "text", "w"}`.
   In a unit that crosses a chapter, `verse` is `"C:V"`.
5. Re-run `python -m biblecore build` (it replays the retrofit file and
   audits); every promoted root should report clean. In a boxed unit, diff
   it afterwards: only tag spans and `data-w` may differ.

## Asking Lane

Questions for Lane (the porter's `questions[]`, wording calls, thread
decisions) go through the **AskUserQuestion popup** with multiple-choice
options, best provisional choice first and marked "(Recommended)", not as a
list in chat. The tool takes 4 questions per call, so batch a longer list
across calls. Lane wants this every time.

## Site

The build's `assets` step writes the app shell (`index.html`, `app/*.js`) and
the generated css from bible-core, with the book name filled in and a content
hash on every link. Each one says "generated, don't edit", and `python -m
biblecore test` reports a hand edit. A change to the shell goes into
bible-core's `biblecore/web/` and reaches the book with the next vendor and
build. Old `#/unit-NN/vN` links still work (the shell jumps to the unit's first
verse numbered N).

## Corpus

**SBLGNT via MorphGNT** (`morphgnt/sblgnt@aaed91e`, pinned in `book.json` and
`biblecore/fetch.py`) plus the **LXX** (`CenterBLC/LXX@4829f37`) for canon leads.
`python -m biblecore corpus`: **1,068 verses, 18,329 words, 1,680 lemmas, every
lemma glossed** from the MorphGNT lexicon (CC BY-SA 3.0). Check the counts
against a printed SBLGNT if they drift on re-fetch. `Matthew-words.tsv` and
`Matthew-reading.txt` are generated; don't hand-edit them. `MatthewSBLGNT.txt`
is the Greek text the research project reads.
