# Thread beat notes — draft

Proposed `note` text for every `opens`/`payoffs` beat in `data/threads.json`
that's currently missing one (81 opens, 13 payoffs — the set `opens_note_required:
false` in `book.json` is standing down for). **Nothing here has been applied**
to `data/threads.json` or any unit fragment; this file is the only thing this
session touched.

Method: for each beat, read the actual English verse in the unit fragment
(`units/unit-NN.html`) and wrote a one-line popover note in the voice of the
notes that already exist on other beats (short, present-tense, quoting this
study's own rendering, no citations beyond what the `ref` field already
gives). Where a thread already carries an overarching `note` describing its
trajectory, that note is the main source for the beat-specific line — this
draft mostly extracts and sharpens what's already been decided there, rather
than inventing new readings.

## Flagged: beats that seem off

Went through every missing beat against its verse text. Nothing looks
mis-tagged or mis-placed — every `ref` lands on a verse that actually carries
the word/phrase the thread tracks. Two small observations, not corrections:

- **come-here** and **fish** both open at the same verse (4:19, "Come — after
  me — and I will make y'all fishers of men") because it's one sentence
  carrying two tracked words. Their draft notes below are deliberately
  differentiated by which word each is about, but if the popover UI shows
  both threads' notes side by side at that verse, they'll read as slightly
  redundant. Not a data problem — just worth knowing before publishing.
- **law-prophets**' own thread-level `note` says the phrase is "now closed"
  (payoff at 7:12), but its `status` field still reads `"open"`. Not a beat
  note issue and out of scope for this file, but flagging in case it's an
  oversight worth a separate fix.

## How to read the tables

Confidence is about the note's wording, not the tagging (which is settled
data policy, not this session's call):
- **high** — the note quotes or closely paraphrases the unit's own text and
  the thread's own trajectory note.
- **med** — the note compresses several verses into one line, or draws a
  connection that's implied rather than stated outright in the thread's own
  note.
