# Matthew — component reference

Generated by `python -m biblecore build` from the components this book enables in `book.json`. Don't edit. The style reference's section 4 lists the base components and any book-specific notes. Any unit may use any component listed here.


## echo — a verse-level cross-book echo ("cf.")

```html
<p class="v"><span class="n">3</span> …</p>
<aside class="echo" data-anchor="1:3">Deut 11:24 gave the same promise; Josh 1:3 repeats it almost word for word.</aside>
```

- **Following sibling** of the verse, like `.gloss`. Never nested in a gloss, always closed.
- `data-anchor` = the verse it follows (`C:V`); build checks it.
- Site prepends "cf." and folds it into the verse's note toggle: don't write "cf.".
- Verse-level link only. One word's history → that root's `echo` field.
- Harvested into `data/canon.json`: don't repeat in `intertext[]`.

**Verified =** target verse read, and link rests on shared words, a shared phrase or a recognised type-scene, not just a shared theme.


## itin — an itinerary as a row of stops (journeys, stations, campaigns)

```html
<section class="block">
  <h2>From Rameses to the plains of Moav <span class="cap">· 33:5–49</span></h2>
  <div class="itin" data-verses="33:5–49">
    <span class="stop">Rameses <sup>33:5</sup></span><span class="arr">→</span>
    <span class="stop">Sukkot <sup>33:5</sup></span><span class="arr">→</span>
    <span class="stop">Etam <sup>33:6</sup></span>
  </div>
</section>
```

- Inside a `section.block`, in line with the text.
- Direct children: only `span.stop` and `span.arr` ("→"), alternating, starting and ending with a stop.
- A stop may carry a `data-root` span (a tracked place name) and a `<sup>` with its verse (`C:V`), or a range (`C:V–V`) when the stop is a whole scene.
- `data-verses` on the `div.itin` when the chips replace the verses (formulaic station list). Prose verses also written out → leave it off; chips are a summary. Tracked spans inside a `data-verses` block need no `data-w`.

**Verified =** stops and order come from the verses. A route the text doesn't give (a reconstruction) → a note, not the chips.


## compare — a rendering spotlight after a verse: the original, this translation, other versions and a note, in labelled rows

A verse sibling (right after the verse's `<p class="v">`, like `.gloss`) that
sets the original beside this translation and others, with a note:

```html
<div class="compare">
  <div class="row"><span class="src">Greek (translit.)</span><span class="txt translit">…</span></div>
  <div class="row"><span class="src">This translation</span><span class="txt">“…”</span></div>
  <div class="row"><span class="src">NASB</span><span class="txt">“…”</span></div>
  <div class="row"><span class="src">Note</span><span class="txt">…</span></div>
</div>
```

Every `.row` starts with its `.src` label. The site hides it behind a ✦ chip
on the verse; several on one verse share one "✦ Rendering" panel. Use it for
a rendering choice worth arguing, not for every gloss.


## synoptic — a parallel passage after a verse (a synoptic parallel), with its own header, rows and a closing take

A verse sibling for a parallel account (Mark/Luke beside Matthew; Kings
beside Chronicles), anchored to the verse it follows:

```html
<aside class="synoptic" data-anchor="5:12">
  <h4>Luke 6:17–26 <span>— short description</span></h4>
  <div class="row"><span class="src">Luke 6:17</span><span class="txt">…</span></div>
  <p class="take">What the difference shows.</p>
</aside>
```

`data-anchor` must match the verse it follows, and the `<h4>` is required
(it is the panel's own title). The site hides each one behind its own ✧ chip.

**How many.** No cap. Every scene another account tells gets checked, and
every one where this book's change is telling (an addition, an omission, a
reordering, a rewording that shifts the point) gets a box: often three to six
a unit. The same event in another account is a synoptic, never an
`aside.story`.


## story — an earlier story told beside a verse: a different, earlier event with the same shape, with its background, what's the same, what's different and what it does here

Verse sibling for a *different, earlier* event with the same shape, told with
its background (Herod's feast beside Pharaoh's birthday feast). Same event in
another gospel, or Chronicles beside Kings = `synoptic`, never a story box.
Link one sentence can carry = `aside.echo`.

```html
<aside class="story" data-anchor="14:6" data-kind="type-scene" data-scene="royal-birthday-feast" data-strength="strong">
  <h4><span class="par-title">Pharaoh's birthday feast</span> <span class="par-ref">Gen 40:20–22</span></h4>
  <p class="par-story">Two to four plain sentences telling the earlier story.</p>
  <ul class="par-match"><li>what's the same</li><li>…</li></ul>
  <p class="par-diff">What's different.</p>
  <p class="par-does">What it does here: irony, reversal, identification, fulfilment, warning.</p>
  <p class="par-later">Later reuse, only if there is one.</p>
</aside>
```

- Follows the verse it bears on, or the last verse of the scene it covers;
  `data-anchor` = that verse. `data-span="14:3–12"` optional.
- `data-kind`: `type-scene`, `story`, `allusion`, `character` or `reuse`. A
  `type-scene` box also names it: `data-scene="<id>"`. Check the canon's
  type-scene list first; a new id is the book owner's call.
- `data-strength`: `strong` or `possible`. Ship a `possible` link when it's
  worth Lane's eye, worded as tentative. A weak link never ships as a story
  box: notes or a footnote.
- Required: `<h4>` with `par-title` and `par-ref`, then `par-story`,
  `par-diff`, `par-does`. **No box ships without a stated difference.**
  `par-ref` must include verses (`Exod 24:15–18`); a bare chapter list
  (`Exod 24; 34`) fails at build. `par-match`, `par-later` optional.
- Site supplies the labels (Same, Different, What it does, Later): don't
  write them. Each box hides behind its own ◈ chip ("Type scene" or "Earlier
  story").
- Transliteration only. No `data-root`, `class="r"` or `class="rl"` inside
  (the occurrence scanner counts every `data-root`). Box rests on shared
  words → put them in the box as evidence; no `aside.echo` for the same
  link. Argument about the link → footnote.
- Harvested into `data/canon.json` (an intertext row per reference, a
  type-scene row for `data-scene`): don't repeat in `intertext[]` or
  `typescenes[]`.
